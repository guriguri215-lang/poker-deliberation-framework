# Codex実行プロンプト例

このリポジトリをCodexのワークスペースとして開き、以下のプロンプトをそのまま入力します。
`$review-poker-hand`、`$run-poker-calculation`、`$audit-poker-claim`は、このリポジトリに
同梱されたSkillを明示的に選ぶ記法です。CLIを直接試す場合は
[READMEのMinimal example](../README.md#minimal-example)を参照してください。

## 1. ハンド履歴を貼り付けて一括レビューする

通常は、次のプロンプトだけで開始できます。`{ここにハンド履歴を貼り付ける}`を、ポーカーサイトから
コピーした履歴または自分で記録した履歴へ置き換えてください。

```text
このプロジェクトのAGENTS.md、同梱Skill、計算ツール、エージェント構成を理解し、
$review-poker-handを使って、レビューに必要なエージェントだけを呼び出してください。
次のポーカーのハンド履歴を正規化し、カード、スタック、アクション、ポットを再構成したうえで、
私の判断とプレイ内容が妥当だったかレビューしてください。

【ハンド履歴】
{ここにハンド履歴を貼り付ける}

入力にない情報やレンジを捏造せず、数値はテスト済みのローカル計算ツールで検証してください。
ハンドレンジが用意されておらず、レビューに外部レンジが本当に必要な場合は、GitHubまたはWeb上の
取得候補を調査し、次の情報を先に提示してください。

- 出典URLと配布元
- ライセンスと再利用条件
- 対象ゲーム、人数、スタック、レーキ、アンティ、ベットサイズ
- 公開日または更新日
- 今回のハンド条件との一致点と相違点
- ダウンロードするファイルとワークスペース内の保存予定場所

ライセンス上利用可能であることを確認し、私が明示的に承認するまでは、ダウンロード、外部送信、
パッケージ導入、外部ソルバー実行を行わないでください。適切な外部レンジが見つからない場合は、
その理由を示し、ASSUMPTIONとして複数の仮定レンジを置く感度分析を提案してください。

FACT / CALCULATED / INFERENCE / ESTIMATE / ASSUMPTION / USER_CLAIM / UNKNOWNを区別し、
ソルバー実行と収束確認なしにGTO、均衡、正確なレンジと断定しないでください。
結論、根拠、仮定、不明点、使用したツールとエージェント、再現コマンドを日本語で報告してください。
```

外部レンジが不要なら、エージェントはローカル情報だけでレビューを続行します。外部レンジが必要でも、
このプロンプトが許可するのは候補調査までです。実際のダウンロードは、候補の説明を確認した後に
別途承認してください。公開レンジも、スタック、レーキ、人数、アクション木などの条件が異なれば、
今回の正確なGTOレンジとしては扱えません。

## 2. リポジトリ内のサンプルハンドをレビューする

```text
$review-poker-hand を使って examples/valid_hand.json をレビューしてください。

- 入力を正規化し、カード、スタック、アクション、ポットの整合性を検証する
- 数値はローカルのテスト済み計算ツールで再計算する
- FACT / CALCULATED / INFERENCE / ESTIMATE / ASSUMPTION / USER_CLAIM / UNKNOWN を区別する
- ソルバー実行と収束確認がない内容をGTOや均衡と断定しない
- 仮定、制限、再現コマンドを含む日本語レポートを返す
- ファイルは変更しない
```

## 3. 自由文ハンドを正規化してレビューする

```text
$review-poker-hand を使って examples/free_text_hand.txt を正規化し、レビューしてください。
入力にない情報は補完せずUNKNOWNのまま残してください。まずアクションの合法性とポットを検証し、
正確な結論に必要な情報が足りなければ、結論を変え得る質問だけをまとめてください。
利用した計算ツールの入力、出力の種類、仮定、警告、再現コマンドを日本語で示してください。
ファイルは変更しないでください。
```

## 4. 決定的な計算を実行する

```text
$run-poker-calculation を使い、examples/pot_odds_input.json を入力として pot_odds を実行してください。
入力の単位と前提条件を確認してから計算し、結果をCALCULATEDとして報告してください。
ToolResultのstatus、numeric_exactness（legacy exactnessだけではなく）、assumptions、warnings、
verification/approximation metadataを確認し、同じ結果を再現できるCLIコマンドも
示してください。暗算による別の数値は追加しないでください。
```

ICMを試す場合は、上のファイル名を`examples/icm_input.json`、ツール名を`icm`に置き換えます。

## 5. 数学的な主張を監査する

```text
$audit-poker-claim を使い、examples/wrong_pot_odds_case.json の主張を監査してください。
USER_CLAIMを原文どおり特定し、仮定と目的関数を明示したうえで、適用可能な決定的計算ツールを
実行してください。主張が誤っている場合は、誤りの種類、計算結果、成立条件、残る不確実性を
明確に訂正し、再現コマンドを付けてください。多数決や未実行のソルバー結果は根拠にしないでください。
```

## 6. 情報不足のトーナメントハンドを確認する

```text
$review-poker-hand を使って examples/incomplete_hand_case.json を確認してください。
chipEV、賞金EV、ICMを混同せず、入力にないブラインド、アンティ、スタック、ポジション、
アクション額、残り人数、ペイアウト、バウンティ、相手レンジを推測しないでください。
現時点で確定できることを示した後、判断を変え得る不足情報だけを優先順に質問してください。
計算不能な項目はUNKNOWNとして扱い、正確な推奨アクションを断定しないでください。
```

## 7. 自分のハンドを項目別に入力するテンプレート

角括弧内を実際の情報に置き換えます。不明な項目は`不明`と書き、個人名、メールアドレス、
認証情報など、分析に不要な情報は入力しないでください。

```text
$review-poker-hand を使い、次のハンドを正規化してレビューしてください。
欠けている情報を捏造せず、まず合法性、ポット、残りスタックを検証してください。
数値計算には $run-poker-calculation のテスト済みツールを使い、仮定、感度、制限、
再現コマンドを含む日本語レポートを返してください。ソルバー未実行ならGTOと断定しないでください。

ゲーム: [NLHE cash / tournament]
人数: [テーブル人数]
ブラインド・アンティ: [SB / BB / ante]
レーキ: [方式。不明なら不明]
残り人数・ペイアウト・バウンティ: [トーナメントの場合。不明なら不明]
Heroの位置と開始スタック: [位置 / スタック]
Villainの位置と開始スタック: [位置 / スタック]
Heroのカード: [2枚]
プリフロップ: [順番、アクション、増分額、到達額]
フロップ: [ボード。順番、アクション、増分額、到達額]
ターン: [カード。順番、アクション、増分額、到達額]
リバー: [カード。順番、アクション、増分額、到達額]
判断したい時点: [ストリートと直前のアクション]
比較したい選択肢: [fold / call / raiseなど]
目的: [chipEV / 賞金EV / ICM / exploitative EV / 不明]
相手レンジまたは観察: [根拠とともに。不明なら不明]
```

実際のオンラインハンド履歴を使う場合は、プレイヤー名を`hero`、`villain-1`のような匿名IDへ
置き換え、テーブル名、ユーザーID、チャット、端末パスなど分析に不要な情報を削除してから入力してください。
